# Architecture / Technique Stack

1. SP1024 tokenizer
2. GDN-Hybrid backbone: \[GDN×5\] → SWA → \[GDN×5\] → SWA\_shared
3. Fixed-predictor evaluation path (no TTT / no SLOT / no eval-time adaptation)
4. MuonEq-R + AdamW training mix
5. EMA = 0.997
6. warmdown = 1000
7. GPTQ int6 + zstd-22 packaging
8. Compressed-code packaging for train\_gpt.py / architectures.py / configs.py to recover artifact headroom

# Compliance

- Fixed-predictor / Track A style submission
- No TTT
- No SLOT
- No RLS
- No eval-time adaptation
- All three artifacts under 16,000,000 bytes
- Training run stays within the 10-minute 8xH100 submission budget

# Notes

XSA telemetry is reported for completeness, but the submitted score is the fixed-model quantized\_bpb result above.

| BPB metric bug: space bytes double-counted (inherited from closed parent PR [#1545](https://github.com/openai/parameter-golf/pull/1545))<br>The decompressed `train_gpt.py` in this PR contains the same `build_sentencepiece_luts` bug that [@SPThole](https://github.com/SPThole) identified in PR [#1545](https://github.com/openai/parameter-golf/pull/1545), and which [@Abhishek8108](https://github.com/Abhishek8108) acknowledged when closing that PR ("The corrected BPB is ~1.18, not 1.028").<br>**Bugged code in this PR (decompressed from the LZMA self-extractor):**<br>```<br># build_sentencepiece_luts, around line 217<br>if piece.startswith("▁"):<br>    has_space[i] = True<br>    base_bytes[i] = len(piece[1:].encode("utf-8")) + 1   # +1 adds the space byte<br>```<br>Then the eval loop adds the same space byte **again**:<br>```<br>tb += (has_leading_space_lut[tgt] & ~is_boundary_token_lut[prev]).to(torch.float64)<br>```<br>**Reference implementation (`train_gpt.py` at repo root, lines 186–189):**<br>```<br>piece = sp.id_to_piece(token_id)<br>if piece.startswith("▁"):<br>    has_leading_space_np[token_id] = True<br>    piece = piece[1:]                       # strip ▁<br>base_bytes_np[token_id] = len(piece.encode("utf-8"))   # NO +1 here<br>```<br>The reference counts the space byte exactly once (in the eval loop, conditioned on `~is_boundary_token_lut[prev]`). The bugged version counts it in both places for every ▁-prefixed token, inflating the byte denominator and deflating the reported BPB.<br>Running the parent PR's corrected LUT on the same checkpoint lands in the ~1.16–1.18 range (per [@Abhishek8108](https://github.com/Abhishek8108)'s own correction on [#1545](https://github.com/openai/parameter-golf/pull/1545)), **not** 1.01671.<br>Bug was missed here because the training code is wrapped in an LZMA self-extractor, which hides it from standard review. Suggest the maintainers decompress and re-score before this shifts the leaderboard. |
